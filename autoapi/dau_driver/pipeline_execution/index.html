dau_driver.pipeline_execution¶

Keyed composed-pipeline job execution against the dau_mm_ohlcv_job shell.

The shell runs keyed {value, key} INT32 pair rows through filter -> map -> ordered grouped aggregation and stages 40-byte group records in the output BRAM (see dau_build.shell_tops generate_mm_ohlcv_job_top_sv and the PIPELINE_* register contract).

A job that timed out or closed out with an error.

last_error carries the shell’s error code when the job closed out with one, and None when there was none to read (a timeout). Carried on the exception rather than left for the caller to read back, because the register only holds the LAST job’s code: a caller that re-reads it after catching this is racing the next job for the reason this one failed.

Poll JOB_STATUS until DONE, raising on timeout or a hardware error flag. Shared by every register-polled job runner so the wait/error semantics stay identical across shells. poll, when given, runs each iteration so concurrent work (e.g. overlap staging) can surface its failure instead of hiding behind this wait’s timeout.

dau_driver.pipeline_execution._read_aligned_records(device, *, address: int, result_length: int, record_bytes: int, count: int, count_label: str, prefix: str = '', validate_record_count: bool = True) → bytes[source]¶

Read the 64-byte-aligned record block that RESULT_LENGTH describes. Returns b"" (and issues no C2H read) when the lane produced no output.

When validate_record_count is set (bar/q1: the count register is an output-record count), the result_length == count * record_bytes invariant is enforced. q6-style aggregate lanes latch an input row count in the count register and emit one fixed-width record, so they pass validate_record_count=False and trust RESULT_LENGTH alone. The empty test keys off RESULT_LENGTH, which is equivalent to count == 0 whenever the invariant holds.

dau_driver.pipeline_execution.device_lane_count(device) → int[source]¶

The number of NoC lanes the RESIDENT shell advertises.

The shell publishes its lane count in the identity registers, so the host has no business assuming one. A composition built with eight lanes driven by a host that assumes four writes four lane windows and silently drops the rest of the result – the kind of wrong answer that looks like a correct short read.

Refuses when the shell advertises nothing (0, which fixed binding tops and any pre-0.2 shell report) rather than falling back to a default: a caller running such a shell knows its geometry and must say so.

dau_driver.pipeline_execution._advertised(value: int) → int[source]¶

All-ones is a word nobody decoded, not a four-billion-row capacity — the same normalization every capability reader applies.

dau_driver.pipeline_execution.device_job_capacity(device) → tuple[int, int][source]¶

(input rows, output records) ONE job may stage on the RESIDENT shell.

These are the shell’s BRAM depths, and the host used to carry them as module constants – one pair for the grouped shell and one for the bar shell, both compiled in. Every shell was therefore batched against the depths of whichever shell the constants were written for, and a shell built with a different depth would have been sliced to the wrong size with nothing to say so. The shell advertises them from register map 0.3.

Refuses when the shell advertises nothing, exactly like the lane count: a 0.2 or earlier shell does not decode these offsets, and a host that guessed here would be reintroducing the constants this replaced.

Reads the two capacity words directly rather than taking a whole identity snapshot: this sits on the per-job path, and a snapshot is ~25 MMIO reads where three will do. Not cached, because a device can be reflashed inside one session – the flywheel does exactly that – and a cached capacity would then describe the previous shell.

dau_driver.pipeline_execution.execute_bar_noc_packed(device, payload: bytes, row_count: int, *, staging, lanes: int | None = None, record_bytes: int = BAR_RECORD_BYTES, validate_record_count: bool = True, timeout_seconds: float = 60.0) → list[tuple[bytes, int]][source]¶

Run one pre-packed batch through a broadcast-NoC shell: one scan computes every lane’s partition concurrently. The lanes must already be configured (configure_bar_noc_lanes). Returns raw record bytes and each lane’s RECORD_COUNT_LOW value.

lanes defaults to the count the DEVICE advertises; the key-partitioned scan shells reuse this runner by passing their own lane count and per-record width when they run a shell that advertises none.

q1’s grouped shell keeps the default validate_record_count (its count register is an output group-record count). q6’s aggregate shell latches an input row count and emits one fixed-width [sum, count] record per lane, so it passes validate_record_count=False and relies on RESULT_LENGTH.
