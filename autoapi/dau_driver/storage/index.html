dau_driver.storage¶

Host-side storage allocation over a platform’s declared tiers.

The dumb half of the allocation lifecycle in STORAGE_AND_NOC.md: the host owns an allocator per shared tier and hands out generation-checked handles; tiles consume grants and never allocate. The handle table this allocator maintains is exactly what a future allocator tile would drive — the API does not change when it does.

Freed storage is never readdressed: free bumps the handle’s generation, and a stale handle raises instead of resolving to reused memory. Exhaustion raises before anything is staged. stage/resolve take any object with write_dma (the duck-typed device convention).

dau_driver.storage._ALLOCATOR_TOKENS¶
class dau_driver.storage.StorageHandle[source]¶

One allocation: identity plus placement. generation is the freed-storage guard — the allocator refuses any handle whose id has been freed since, so reused space is never readable through an old name — and allocator binds the handle to the allocator that issued it, so a handle from one tier can never free or address another’s memory. Every operation trusts only the allocator’s LIVE record, never the handle’s own copy of base/capacity.
