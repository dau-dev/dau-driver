test_fleet.test_poll_yield_reaches_every_pipeline_status_wait(tmp_path) → None¶

poll_yield_seconds exists for pure-Python transports, whose register read would otherwise hold the GIL and serialize co-running pipelines. The real transports release it (os.pread / ctypes), so the default is to spin — assert the plumbing deterministically rather than a wall-clock split, which is not a reliable signal.

test_fleet.test_a_stateful_composition_cannot_run_on_a_fleet(tmp_path) → None¶

Batches are pulled from ONE shared source by whichever device is free, so a key’s rows land on whichever cards happen to be idle and per-key state splits across devices that never see each other’s rows. Key-partitioning the input does not save it — the affinity would have to be device-wide, and demand-driven scheduling is what makes the fleet self-balancing. This is the same guard run_scan_batches applies to position-sliced batches, one level up.
